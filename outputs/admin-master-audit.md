## หลักการสิทธิ์และหน่วยงาน

- Super Admin เดิมและ System Admin ใช้ authority ระดับระบบ โดยไม่ต้องได้รับสิทธิ์จากบทบาทหน่วยงานหรือสมาชิกโรงเรียน
- การจัดการข้อมูลที่มีเจ้าของหน่วยงานยังระบุหน่วยงานปลายทางชัดเจน หน้าข้อมูลหลักและเมนูโรงเรียนเปิดหน่วยงานที่เหมาะสมให้ และเปลี่ยนหน่วยงานจากหน้านั้นได้
- ผู้ใช้ทั่วไปยังถูกตรวจ membership, permission และขอบเขตนักเรียน/ห้องเรียนตามเดิม มีการทดสอบป้องกันการข้ามขอบเขต
- รหัส master ที่ระบบใช้ในการทำงานและฟิลด์ชื่อสถานะที่ถูกล็อกยังแก้ไขไม่ได้ ใช้การเปิด/ปิดใช้งานตามที่ API รองรับ

## การตรวจสอบ

- Unit/integration: frontend 51 และ backend 168 รายการ ผ่านทั้งหมด เปิดการทดสอบฐานข้อมูลที่ปกติถูกข้ามด้วย `SCHOOL_DB_TESTS=1`, `PDPA_DB_TESTS=1`, `REFERRAL_DB_TEST=true`
- MySQL 8.4.8: ทดสอบข้อมูลนักเรียน รายละเอียดและ export; workflow โรงเรียน; master ทุกหมวดในหน่วยงานโรงพยาบาลและโรงเรียน รวมการอ่าน เพิ่ม แก้ไข ปิดใช้งาน และถอดรหัสแม่แบบ ข้อมูลจากการทดสอบที่แก้ไขถูก rollback
- Browser รอบกว้าง: 81 ผ่าน และ 33 ข้ามตามเงื่อนไขเดิมของ suite รวม smoke test หน้าสาธารณะและหน้าผู้ดูแล เมนูตามสิทธิ์ การจัดการโรงเรียน และ workflow บน desktop/mobile
- Browser รอบยืนยัน: 34 ผ่าน ครอบคลุม master, บัญชีผู้ใช้, โรงเรียน, การส่งออก และเส้นทาง System Admin ที่ไม่มี membership
- Browser ขั้นสุดท้ายหลังปรับรายละเอียด CSS: 12 ผ่าน บน desktop/mobile รวมการสลับหน่วยงานและโรงเรียน การเพิ่ม/แก้ไข master การลองใหม่ และการจำกัดสิทธิ์ผู้ใช้ทั่วไป
- ชุด `admin-workspace.spec.js` ตรวจ accessibility ด้วย axe ของหน้าข้อมูลหลักทั้ง desktop/mobile รวมความกว้างหน้าและความสูงช่องค้นหา
- Production build ผ่าน มีคำแนะนำเรื่องขนาด JavaScript chunk จาก Vite ที่มีอยู่ใน dependency graph
- ตรวจภาพด้วยข้อมูลจำลอง ไม่มีข้อมูลผู้รับบริการจริงในภาพ
