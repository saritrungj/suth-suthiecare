# สี การจัดวาง และการโต้ตอบร่วมกัน

ทิศทางของ Suthie Care คืออบอุ่น เป็นมิตร และอ่านข้อมูลสุขภาพได้ชัดเจน ใช้ส้มหลักของแบรนด์กับพื้นที่เน้น ส้มเข้มสำหรับปุ่มที่มีตัวอักษรขาว และ Sarabun ร่วมกัน สีสถานะและความเสี่ยงยังแสดงความหมายเดิม

## แหล่งที่รับผิดชอบ

| ส่วน                                             | แหล่งกลาง                                                 |
| ------------------------------------------------ | --------------------------------------------------------- |
| สี ฟอนต์ ระยะ และลำดับชั้น                       | `app/src/styles/tokens.css`                               |
| ปุ่ม ช่องกรอก หัวข้อ ตัวกรอง ตาราง และแท็บ       | `app/src/components/ui/index.jsx`, `component-system.css` |
| ความกว้าง ระยะขอบ การขึ้นแถว และพื้นที่เลื่อน    | `layout-system.css`                                       |
| focus / active / disabled และรายละเอียดการโต้ตอบ | `interaction-system.css`                                  |
| รูปลักษณ์หน้าต่างเดิมและ SweetAlert              | `modal-system.css`                                        |
| โฟกัสและการซ้อนหน้าต่าง                          | `useDialogFocus.js`                                       |

CSS รายหน้าต้องจำกัดขอบเขตใน root ของหน้านั้น หลีกเลี่ยง `td button`, `.filter-bar`, `.modal-overlay` หรือ `.label-icon` แบบไม่มีเจ้าของ เพราะ stylesheet ที่โหลดระหว่างสลับเมนูยังมีผลต่อหน้าถัดไป Dashboard ใช้ `.dashboard-page`; RiskCases ใช้ `.admin-wrapper2`; เนื้อหา FAQ ที่เป็น portal ใช้ `.hc-dialog`

## การโต้ตอบ

- ปุ่มและช่องกรอกใช้ความสูงอย่างน้อย 44px กับมุม 10px ไอคอนและข้อความจัดแนวกลางโดยไม่เปลี่ยนขนาดเมื่อ hover
- Hover ทำให้สีเข้มขึ้น; focus จากคีย์บอร์ดมีเส้นขอบชัด; active มี feedback ขณะกด; disabled ลดความเข้มและกดซ้ำไม่ได้ แท็บที่เลือกยังคงสีสถานะเมื่อ hover
- ช่องกรอกต้องมี label ที่สัมพันธ์กัน ข้อผิดพลาดใช้ `aria-invalid` และเชื่อมข้อความด้วย `aria-describedby` ฟอร์มเจ้าหน้าที่รองรับ Enter และโฟกัสช่องที่ผิดก่อน
- ระหว่างบันทึกปิดการกดซ้ำและการปิดหน้าต่าง เมื่อบันทึกล้มเหลวเก็บข้อมูลในฟอร์มไว้และให้ข้อความผิดพลาดกดได้เหนือหน้าต่าง

## หน้าต่างและ dropdown

ใช้ Dialog สำหรับหน้าต่างใหม่; ใช้ DialogFrame เมื่อเนื้อหามีโครงเฉพาะงาน ทั้งสองส่งเนื้อหาไปที่ body, ทำพื้นหลัง inert, เก็บ Tab ภายใน, ปิดเฉพาะหน้าต่างบนสุดด้วย Escape และคืนโฟกัสหลังปิด หน้าต่างลูกที่มาจากเมนูซึ่งถูกถอดออกจะคืนโฟกัสเข้าหน้าต่างแม่

ส่วนหัวและท้ายไม่หดเมื่อเนื้อหายาว เนื้อหามีพื้นที่เลื่อนของตนเอง ปุ่มปิดอยู่ข้างหัวข้อ แทนการวางทับข้อความ ปุ่มท้ายหน้าต่างเรียงตรงกับลำดับ DOM บนมือถือ

ลำดับชั้นใช้ navigation 1000 → backdrop 1100 → drawer 1200 → dropdown 1600 → dialog 20000 → confirmation 30000 Dropdown ภายใน dialog อยู่ใน dialog และคำนวณพื้นที่ด้านบน/ล่างตาม viewport ที่เห็นจริง จึงไม่ต้องใช้ z-index สูงสุดของเบราว์เซอร์

## แบบประเมินและแบนเนอร์

แบบประเมินที่ยังไม่กำหนด theme ใช้สี action และ canvas กลาง ตัวสร้างฟอร์มอ่านค่าเดียวกันผ่าน `styles/theme.js` เพื่อให้ตัวเลือกสีได้ค่า hex จริง Theme ที่ผู้สร้างบันทึกไว้ยังมีผลตามเดิม

ตัวเลือกไฟล์แบนเนอร์เป็น native file input ที่เข้าถึงด้วยคีย์บอร์ดได้ พื้นที่เลือกรูปมี focus ring ภาพหลังตัดย่อภายในหน้าต่าง และปุ่มยืนยันตัดรูปพร้อมใช้เมื่อคำนวณกรอบเสร็จ

ตัวสร้างฟอร์มแยกหัวเครื่องมือออกจากพื้นที่เลื่อนเนื้อหา หัวแบบประเมินที่ผู้สร้างกำหนดเลื่อนไปพร้อม canvas ปุ่มคำสั่งเป็น native button; Undo/Redo ใช้ disabled จริง บนมือถือไม่ใช้ flex-basis ของแถวไปกำหนดความสูงของหัวเครื่องมือ ปุ่มตัวเลือกแสดงเมื่อใช้คีย์บอร์ดหรือสัมผัส และแถบเครื่องมือด้านล่างเลื่อนภายในได้เพื่อคงพื้นที่กด 44px

## การตรวจ

- `e2e/interface-consistency.spec.js`: สลับเมนูจริง, hover/focus, หน้าต่าง 5 รูปแบบ, การบันทึกล้มเหลว, dropdown, หน้าต่างลูกของเคส, สีเริ่มต้น/สีที่กำหนดเอง และอัปโหลด/ตัดรูปด้วยคีย์บอร์ด ที่ 320, 900 และ 1440px
- `e2e/responsive-layout.spec.js`: 42 เส้นทาง รวมแนวนอนและจอกว้าง
- ชุดทดสอบเดิม: เคส/ข้อมูลส่วนบุคคล, กราฟ, โรงเรียน, component accessibility, auth และแบบประเมิน
- หลักฐานรอบนี้อยู่ใน `outputs/interface-consistency/` ใช้ข้อมูลสาธิตและ Chromium emulation การทดสอบอุปกรณ์จริงยังเป็นขั้นตอนแยก
