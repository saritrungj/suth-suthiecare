# กติกาการจัดหน้า Suthie Care

คงสีส้มอบอุ่นและ Sarabun ใช้ลำดับงานร่วมกัน: ชื่อหน้าและคำสั่งหลัก → ตัวกรอง → ข้อมูล → คำสั่งท้ายรายการ แต่ละกลุ่มต้องมีระยะที่แยกออกจากกันชัดเจน โดยไม่ครอบทุกอย่างด้วยการ์ดหลายชั้น

## แหล่งกลาง

- `app/src/styles/tokens.css`: ระยะขอบหน้า 16–40px, ช่องว่างระหว่างส่วน 24–32px, ช่องว่างกลุ่มปุ่ม 12px, ความกว้างอ่าน 880px / หน้าสาธารณะ 1200px / หน้าจัดการ 1500px และลำดับชั้นหน้าต่าง
- `app/src/styles/component-system.css`: รูปลักษณ์ส่วนประกอบร่วม
- `app/src/styles/layout-system.css`: ความสูงพื้นที่ทำงาน ความกว้าง การตัดบรรทัด การจัดกลุ่ม และการปรับตามหน้าจอ โหลดหลัง component styles

AdminLayout เป็นเจ้าของความสูง `100dvh` และพื้นที่แถบเมนูบนมือถือ หน้าในระบบเติมพื้นที่ที่เหลือใต้แถบ Export ด้วย flex และ `min-height:0` ส่วนเนื้อหาเลื่อนได้ อย่าใช้ body padding หรือความสูงเต็ม viewport ซ้ำในหน้าลูก

## การปรับตามพื้นที่

| เงื่อนไข | พฤติกรรม |
| --- | --- |
| หน้าจอกว้าง | เนื้อหาจัดการหยุดที่ 1500px จัดกึ่งกลาง ตัวเลขแดชบอร์ด 4 คอลัมน์ |
| ≤1100px | สมัครสมาชิกเป็นคอลัมน์เดียว ส่วนแนะนำกระชับก่อนเข้าฟอร์ม |
| ≤1024px | เมนูเจ้าหน้าที่เป็น drawer; ตัวแก้ไขฟอร์มใช้พื้นที่จริงใต้เมนูและ Export; สรุปแดชบอร์ด 2 คอลัมน์ |
| ≤760px | กลุ่มปุ่มและตัวกรองขึ้นแถวใหม่ ฟอร์มจัดการเป็นคอลัมน์เดียว รายการห้องเรียนไม่อัด 4 คอลัมน์ |
| ≤600px | ข้อมูลประวัติจัดชิดซ้าย ชื่อและคำสั่งแก้ไขอ่านต่อกันได้; สรุปข้อมูลโรงเรียนเป็น 2 คอลัมน์ |
| ≤359px | สรุปแดชบอร์ดเป็นแถวสั้นเพื่อเห็นข้อมูลสำคัญเร็วขึ้น |
| จอสัมผัส | ปุ่มเครื่องมือสาธารณะและปุ่มแก้ไขประวัติอย่างน้อย 44px; ช่องกรอกบัญชี 16px |
| แนวนอนเตี้ย | หน้าต่างจำกัดความสูงตามพื้นที่จริง เนื้อหาภายในเลื่อนได้ |

รักษาลำดับ DOM ให้ตรงกับลำดับที่มองเห็น ปุ่มตัวอย่างฟอร์มเรียงตาม DOM เมื่อยุบเป็นแนวตั้ง ตารางและคำถามแบบ matrix เลื่อนแนวนอนภายในกรอบของตนเอง ไม่บีบข้อมูลจนอ่านยาก แถบเครื่องมือและท้าย dialog เผื่อ safe area; footer สาธารณะอยู่ใน document flow เพื่อรองรับข้อความที่ยาวขึ้น

ลำดับชั้น: navigation 1000 → backdrop 1100 → drawer 1200 → dialog 20000 → confirmation 30000 สไตล์แบบประเมินความพึงพอใจจำกัดใน `.suth-evaluation-dialog` เพื่อไม่รั่วไปยังหน้าต่างของงานอื่น

## หลักฐานตรวจ

`app/e2e/responsive-layout.spec.js` ใช้ข้อมูลสังเคราะห์ ตรวจ 42 เส้นทางที่ 320×740, 900×1000 และ 1440×1000: horizontal overflow, ความสูงพื้นที่ทำงาน, ขอบฟอร์มสมัครสมาชิก และ runtime errors เพิ่มกรณีเครื่องมือสร้างฟอร์ม/หน้าต่างที่ 844×390 และขอบเนื้อหาที่ 2560×1440

ภาพและ JSON อยู่ใน `outputs/responsive-unification/` ตรวจผ่าน Chromium browser emulation ซึ่งยังไม่แทนการทดสอบแป้นพิมพ์เสมือนและ safe area บนอุปกรณ์จริง

```powershell
cd app
pnpm exec playwright test --config playwright.responsive.config.mjs
```

ตรวจการทำงานเดิมด้วย auth/public/result/component integration tests, unit tests และ production build ส่วนตัวตรวจ layout เชิงโค้ดบันทึกใน `layout-scan-final.json` ควบคู่ภาพจริง ไม่ใช้ผล scan เพียงอย่างเดียวตัดสินคุณภาพ
