# แนวทางรวม Design ของ Suthie Care

วันที่ 15 ตุลาคม 2569 — ข้อเสนอจากการอ่านโค้ดปัจจุบันและภาพตัวอย่างใน outputs

## ทิศทางที่ผู้ใช้เลือก

อบอุ่น เป็นมิตร ใช้ส้มเดิมของ Suthie Care เป็นสีหลัก พร้อมพื้นสว่างสำหรับอ่านข้อมูลนาน ๆ
เอกสารนี้เสนอแนวทางปรับระบบ ยังไม่ได้เปลี่ยน UI หรือแทนที่ app/DESIGN.md

## สิ่งที่มีอยู่แล้ว

- app/PRODUCT.md และ app/DESIGN.md กำหนดแบรนด์ส้ม ฟอนต์ Sarabun พื้นเทาและการ์ดขาว
- app/src/styles/tokens.css รวมสีข้อความ พื้นผิว สีสถานะ ขนาดปุ่ม 44px และมุมโค้ง 10/14px
- app/src/styles/admin-theme.css รวมสีของส่วนผู้ดูแลผ่าน .admin-shell
- มี button-system.css, filter-system.css, modal-system.css และ case-workspace.css สำหรับงานที่ใช้ซ้ำ
- โรงพยาบาล โรงเรียน และผู้ดูแลระบบใช้รูปแบบการทำงานต่างกัน จึงควรใช้ภาษาการออกแบบเดียวกันโดยจัดเนื้อหาให้เหมาะกับงาน

## สาเหตุที่หน้าอาจดูไม่เป็นชุดเดียวกัน

1. CSS รายหน้ามีสีแบบระบุค่าตรง รวมถึงหลายตระกูลสีและเงา ทำให้เปลี่ยน tokens อย่างเดียวไม่ครอบคลุม
2. dashboard.css และ ClinicManager.css มีการใช้ทั้ง Sarabun และ Noto Sans Thai ต่างจากแนวทางหลัก
3. admin-theme.css ใช้ตัวเลือกคลาสหลายรายการและ !important เขียนทับ CSS เดิม จึงยังขึ้นกับโครงสร้างและความแรงของ selector
4. button-system.css ประกาศสีปุ่มเดิม #f47932 แยกจาก --suth-action โดย admin มีการ remap แต่ส่วนสาธารณะอาจได้รับค่าอีกชุด
5. index.css ยังมีสีลิงก์และ hover เริ่มต้น #646cff / #535bf2 ที่ไม่ใช่สีแบรนด์
6. แนวทางใน DESIGN.md ระบุพื้นเทา แต่ admin-theme.css ใช้พื้นอมอุ่นและ sidebar ส้มเข้มแล้ว จึงควรตกลงค่าจริงก่อนปรับเอกสารให้ตรงกัน

ข้อค้นพบนี้อ้างอิงโค้ดและภาพที่มีอยู่ ไม่ใช่ผลตรวจทุก route จากระบบที่กำลังรัน

## วิธีทำให้ทุกหน้าเป็นทิศทางเดียวกัน

1. **Tokens เป็นแหล่งค่าหลัก**: แยก brand, action, surface, text, border, risk และ workflow status ให้ชัด ให้ตัวแปรระบบเก่าอ้างถึง tokens แทนการประกาศสีใหม่
2. **สร้างส่วนประกอบใช้ร่วมกัน**: PageHeader, Button, FilterBar, FormField, DataTable, StatusBadge, EmptyState และ Dialog/Drawer รวมรูปแบบและสถานะ focus, disabled, loading, error
3. **กำหนดแม่แบบหน้า**: หน้ารายการใช้หัวหน้า → ตัวกรอง → ตาราง/รายการ → แบ่งหน้า; หน้าฟอร์มใช้หัวหน้า → ส่วนข้อมูล → แถบบันทึก; dashboard ใช้กติกาตัวอักษร พื้นผิว และสีเดียวกัน
4. **ใช้ขนาดร่วมกัน**: Sarabun; หัวหน้า 24px; หัวข้อส่วน 18–20px; เนื้อหา 15–16px; ระยะห่างฐาน 4/8/12/16/24/32px; controls 44px; มุม control 10px และพื้นที่ทำงาน 14px ค่าที่ยังไม่มีใน tokens ให้เพิ่มหลังยืนยันแนวทาง
5. **เปลี่ยนทีละกลุ่ม**: เริ่ม shell และ components กลาง → dashboard/ข้อมูลเคส → งานโรงเรียนและจัดการข้อมูล → ตั้งค่า → login และหน้าสาธารณะ โดยรักษาสีเฉพาะแบบฟอร์มที่ผู้สร้างกำหนดไว้
6. **ตรวจกลุ่มหน้าตัวแทน**: desktop และ mobile, ข้อมูลยาว/ว่าง/ผิดพลาด, keyboard focus และ contrast ก่อนนำกติกาไปใช้ครบทุกหน้า

## รูปแบบให้เลือกสีในระบบจริง

- เพิ่ม Appearance ในการตั้งค่าระบบ: ชุดสีสำเร็จรูป, สีแบรนด์กำหนดเอง, ตัวอย่างก่อนบันทึก และคืนค่าเริ่มต้น
- แนะนำให้ผู้ดูแลระบบเลือกธีมเดียวของทั้งระบบก่อน เพื่อให้ทุกหน่วยงานใช้ทิศทางเดียวกัน
- บันทึก theme ID และสีที่อนุญาตไว้ส่วนกลาง แล้วใช้ data-theme บน app root เพื่อเปลี่ยน CSS variables ทุกหน้า
- สีที่เลือกเองต้องสร้าง action/hover/tint/focus ที่อ่านได้ รวมทั้งตรวจข้อความบนพื้นจริง ไม่เปลี่ยนเฉพาะ primary
- สีความเสี่ยงและสถานะไม่เปลี่ยนตามธีม สีกราฟที่ผู้ใช้กำหนดต้องพิจารณาแยกจากสีระบบ
- ต้องตรวจระบบตั้งค่าที่มีอยู่ก่อนเลือกรูปแบบ API/ฐานข้อมูล; เอกสารนี้ยังไม่กำหนดหรือเปลี่ยนสัญญา API

## ขอบเขตการทำงานครั้งนี้
