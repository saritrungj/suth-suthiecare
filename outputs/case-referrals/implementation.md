# ส่งต่อเคสระหว่างหน่วยงาน — รุ่นเบื้องต้น

เพิ่มแท็บ **ส่งต่อ** ในรายละเอียดเคสของโรงพยาบาล และในแฟ้มนักเรียนสำหรับเจ้าหน้าที่ที่มีสิทธิ์ดูเคส เพิ่มเมนู **ส่งต่อระหว่างหน่วยงาน** (`/admin/referrals`) สำหรับรายการรับเข้าและส่งออก

## วิธีใช้

1. เลือกหน่วยงานที่กำลังใช้งานหนึ่งแห่ง แล้วเปิดเคส → ส่งต่อ
2. เลือกหน่วยงานปลายทางที่เปิดใช้งาน และเขียนเหตุผลส่งต่อไม่เกิน 1,000 ตัวอักษร
3. ปลายทางเปิดเมนูส่งต่อระหว่างหน่วยงาน → รับเข้า → เปิดรายการ → รับเรื่อง
4. ปลายทางเปลี่ยนเป็นกำลังดำเนินการ และเสร็จสิ้น พร้อมบันทึกผลสรุป เมื่อปฏิเสธรับเรื่องต้องระบุเหตุผลด้วย
5. ต้นทางดูผลผ่านรายการส่งออก หรือรายการส่งต่อของเคสเดิม

ทั้งสองฝ่ายเพิ่มบันทึกสรุปได้ระหว่างที่รายการยังดำเนินการอยู่ ต้นทางยกเลิกได้ก่อนปลายทางรับเรื่อง รายการที่สิ้นสุดแล้วเก็บประวัติและไม่เปิดให้แก้ไข

## ข้อมูลที่แชร์

แชร์เฉพาะชื่อที่ปิดบังนามสกุล ชื่อฟอร์มอ้างอิง หน่วยงานต้นทาง/ปลายทาง เหตุผลส่งต่อ สถานะ และประวัติข้อความสรุปที่เจ้าหน้าที่ตั้งใจบันทึกร่วมกัน พร้อมหน่วยงาน ผู้บันทึก และเวลา

คำตอบแบบฟอร์ม บันทึกภายในเคส เลขบัตร เบอร์โทร และรหัสบุคคลไม่ถูกส่งให้ปลายทางโดยอัตโนมัติ เหตุผลและบันทึกเป็นข้อความอิสระที่ทั้งสองฝ่ายเห็น จึงควรกรอกเฉพาะข้อมูลเบื้องต้นที่จำเป็น

## การ Sync

ต้นทางและปลายทางอ่านรายการส่งต่อเดียวกันจากฐานข้อมูล สถานะและบันทึกจึงใช้ข้อมูลชุดเดียวกัน หน้ารายการ รายละเอียด และประวัติในเคสตรวจข้อมูลใหม่ทุก 15 วินาทีเมื่อหน้าแสดงอยู่ และมีปุ่มโหลดล่าสุด

ขณะกำลังเขียนบันทึกหรือเลือกการดำเนินการ รายละเอียดพักการโหลดอัตโนมัติเพื่อรักษาฉบับที่เจ้าหน้าที่กำลังดู หากอีกฝ่ายบันทึกก่อน ระบบตอบ 409 และให้โหลดล่าสุด ข้อความที่กำลังเขียนยังคงอยู่

สถานะการส่งต่อแยกจากแปดสถานะติดตามเคสเดิม และยังไม่สร้างแฟ้มผู้รับบริการหรือคัดลอกเคสเต็มที่ปลายทาง

## สิทธิ์และการตรวจสอบ

| การทำงาน                                       | สิทธิ์                          |
| ---------------------------------------------- | ------------------------------- |
| ดูรายการและประวัติในหน่วยงานที่เป็นคู่ส่งต่อ   | `cases.view`                    |
| เลือกปลายทางและส่งต่อ                          | `cases.assign` และ `cases.view` |
| เพิ่มสรุปและเปลี่ยนสถานะตามบทบาทต้นทาง/ปลายทาง | `cases.update` และ `cases.view` |

API ตรวจเจ้าของเคสต้นทาง และจำกัดการอ่าน/แก้ไขให้หน่วยงานต้นทางหรือปลายทางเท่านั้น มุมมองทุกหน่วยงานต้องเลือกหน่วยงานเดียวก่อนใช้งาน

การเขียนสถานะและประวัติอยู่ใน transaction เดียวกัน มี version ป้องกันบันทึกทับ และ unique constraint ป้องกันส่งเคสหลักเดียวกันซ้ำไปปลายทางเดิมระหว่างที่รายการเดิมยังเปิดอยู่ ข้อความที่แชร์และชื่อถูกเข้ารหัสในฐานข้อมูล เคสที่มีประวัติส่งต่อไม่สามารถลบทิ้งผ่าน API ลบเคสได้

## ติดตั้งฐานข้อมูล

Migration: `server/migrations/20261003_case_referrals.sql`

จากโฟลเดอร์ `server` หลังตั้งค่า environment ของฐานข้อมูลเป้าหมาย:

```powershell
npm run migrate:case-referrals -- --apply
```

เพิ่มตาราง `case_referrals` และ `case_referral_updates` ได้ติดตั้งในฐานข้อมูล local ที่ใช้ในการพัฒนาแล้ว ยังไม่ได้ deploy ไป production

## การตรวจสอบ

- Backend: ทดสอบการจำกัดสิทธิ์ ขอบเขตหน่วยงาน การซ่อนข้อมูลเชิงลึก การเปลี่ยนสถานะ version conflict และ transaction rollback
- MySQL local: ทดสอบ constraint ป้องกันส่งซ้ำด้วยข้อมูลจำลอง และ rollback ข้อมูลจำลองทั้งหมด
- Browser: ใช้ข้อมูลจำลองแยก session ต้นทางและปลายทาง ทดสอบส่ง/รับ/ปิดงานและเห็นสรุปร่วมกัน รวมถึงหน่วยงานที่สามเปิดดูไม่ได้ ทั้ง desktop และ mobile
- ภาพหน้าจอใน `.impeccable/review/referrals/` เป็นข้อมูลจำลอง ไม่มีข้อมูลผู้รับบริการจริง

## ขอบเขต API

| Method | Path                               | ใช้งาน                                            |
| ------ | ---------------------------------- | ------------------------------------------------- |
| GET    | `/api/case-referrals/destinations` | หน่วยงานปลายทางที่เปิดใช้งาน                      |
| GET    | `/api/case-referrals`              | รายการรับเข้า/ส่งออก กรองสถานะ แบ่งหน้า 50 รายการ |
| GET    | `/api/case-referrals/:id`          | รายละเอียดและประวัติสรุป                          |
| POST   | `/api/case-referrals`              | ส่งต่อเคส                                         |
| POST   | `/api/case-referrals/:id/updates`  | เปลี่ยนสถานะ/เพิ่มสรุปพร้อม version               |
